# Knowledge base

This dependency-free host plugin and classic-script Web client support **DSH `0.2.1-rc.2`** through the manifest range `engines.dsh: >=0.2.1-rc.2 <0.3.0`; the manifest declares no `@deepseek-ai/dsh` peer. It will give employees the 「知识库」 sidebar panel, the composer scope control and the retrieval tool over the platform's RAGFlow proxy (stage 2, group 15).

## Scope

15.1 delivered the skeleton, the image delivery and the catalog registration; 15.2 added the 「知识库」 panel; 15.3 added the composer scope control and the per-turn scope snapshot; 15.4 adds the retrieval tool `knowledge_base_search` and its source card.

- The plugin code, manifest and patch hold no RAGFlow address, key or retrieval parameter. The RAGFlow key stays in the platform backend; the plugin only ever talks to the platform, and the browser only ever talks to this instance's own DSH routes.

### Availability

The plugin is usable on an instance only when the overlay gives a valid `{ platformUrl }` (below) **and** `DSH_TEAM_INSTANCE_TOKEN` is exactly 64 lowercase hex characters. The host half (`index.js`, plugin name `dsh-team-knowledge-base`, `inject = ['connection']`) publishes the page global `__DSH_TEAM_KNOWLEDGE_BASE__ = { available }` through the released `webserver/index-inject` row in both cases, as `platform-nav` publishes its own. Without an address (`published-loopback`, an employee's older overlay) or without a valid token it registers no route and publishes `{ available: false }`; the client then registers no panel and sends no request. The token never reaches the page global, a log line or an answer.

### Host routes

When available, the host half registers two exact `GET` routes on DSH's shared `/api` channel through `ctx.connection.fetch.register` (DSH authenticates the browser before the handler runs: 401 unauthenticated, 403 untrusted Host/Origin or a non-owner Peer):

- `GET /api/knowledge-base.datasets` takes no query; any query string, even a bare `?`, or a fragment answers `invalid-request` without a platform request. It forwards to `<platformUrl>/_platform/instance-api/ragflow/datasets`.
- `GET /api/knowledge-base.documents?datasetId=<32 lowercase hex>&page=<1..999999>&pageSize=<1..100>[&keywords=…]` parses its raw query as strictly as the platform proxy: percent-decoded, `+` as a space, and an unknown, repeated, valueless or undecodable item, a fragment, or blank (U+0085 included) or over-256-UTF-8-byte `keywords` answer `invalid-request` without a platform request. It forwards to `<platformUrl>/_platform/instance-api/ragflow/datasets/<id>/documents?page=&page_size=[&keywords=]`.

Each platform request sends `Authorization: Bearer <DSH_TEAM_INSTANCE_TOKEN>` with `redirect: 'manual'`, has one 25-second deadline through the end of the body and a 2 MiB body limit (a parameter of the request function), is never retried, and is aborted when the browser disconnects or the plugin is disposed. Both routes always answer HTTP 200 with `content-type: application/json` and `cache-control: no-store`, and a closed body: `{ result: 'ok', datasets: [{ id, name }] }`, `{ result: 'ok', total, documents: [{ id, name }] }` or `{ result }` with `not-configured`, `unavailable`, `timeout`, `upstream-error` or `invalid-request`. A platform 200 whose body passes the plugin's shape check is forwarded with only those fields, and the platform's own `result` passes through; a 3xx, 401 or other non-200, an oversized, unparseable or malformed body is `upstream-error`; a transport failure is `unavailable`; the deadline is `timeout`. Logs carry fixed text and the result only (a 401 adds one fixed line about the instance token), never `keywords`, the token, the platform address or a body.

### Panel

DSH 0.2.1 has no content slot in the left sidebar, so the panel follows the released panels (定时任务): the client (`client.js`, `inject: ['slots']`, React from the runtime seed) registers one `sidebar.panellist` row `{ id: 'knowledge-base', order: 20, label: () => '知识库' }` with an inline SVG glyph and a `main` page under the same key, which `layout.selectPanel` requires. The manifest's `dsh.client.inject` therefore also names `@deepseek-ai/dsh-client-ui-layout`. All texts are fixed Chinese; the page uses plain DOM elements and DSH's CSS variables.

The page lists the libraries, filters them by name on the client (case-insensitive substring, ignored when blank), and expands a library into its files, 20 per page with 「上一页」/「下一页」 and 「第 x / N 页」, filtered by file name through `keywords` (Enter or 「筛选」, back to page 1; a blank filter of any length clears it; any other over 256 UTF-8 bytes is refused with the separate hint 「筛选词过长」 and no request). 「刷新」 reloads the list and collapses every library. Every region carries `data-dsh-team-kb-state`: `loading`, `not-configured` (「知识库未配置」, without a list, search or retry; 「刷新」 stays so the list loads once RAGFlow is configured), `failed` (any other failure, with 「重试」), `empty`, `no-match` and `list`, each with its own text. An empty page past the end of a positive total falls back once to the last page. The list and each library hold at most one request: a new one aborts the previous, and a superseded answer is dropped even when its request ignored the abort and answers last. Every answer body is read before the panel changes. Browsing reads and writes no Session or scope data.

### Retrieval scope

Each Session's scope lives only in its own log. When available, the host half registers, through `ctx.inject(['sessionProjections', 'commands'], …)`, the command `/kb-scope` (`definitionId: '@dsh-team/knowledge-base'`, input hint `<json>`, no attachments) and the Session projection `kbScope` (`stateVersion: 1`); without those services the panel works as before and the control has no projection to show. Plugins outside DSH must not call `appendPluginRecord`, so the released command runtime records the scope: it appends `command/run` (with the raw arguments) before the handler and `command/done` after it, both ordinary persisted, model-invisible events.

- The argument is one JSON line, `{"datasetIds":null}` (every library, later ones included) or `{"datasetIds":[…]}` with 0..1000 distinct 32-lowercase-hex IDs (`[]` retrieves nothing). It is trimmed before parsing; any other shape, an extra key, a duplicate ID or more than 40000 UTF-8 bytes answers the fixed `知识库范围参数无效` without echoing the input. Success answers 「知识库范围：全部」, 「知识库范围：不检索」 or 「知识库范围：N 个」.
- The fold state is `{ child, selection, running, turn }`; its wire view is `{ child, selection, turn }`. `child` is `header.origin === 'subagent'` (an employee fork carries a parent but no origin and is its own root). A `kb-scope` `command/run` whose arguments parse becomes `running`; its paired `command/done` sets `selection` only when `kind` is `success`; a run without its done (a crash), bad arguments, a failed or unpaired done change nothing. Every `turn/start` snapshots `turn = { turn, scope: selection }`; other events return the same state.
- A Session without records reads `selection: null`, so a new Session searches every library (D10), and existing Sessions read the same. Changing the fold semantics later needs a new `stateVersion`.
- Snapshot timing: a change made while a turn runs is appended after that turn's `turn/start` and applies from the next turn. A submission queued behind a running turn takes the selection current when its own turn actually starts, not when it was queued (accepted residual).
- `/kb-scope …` also appears in the composer's `/` menu (the released command descriptor has no hidden flag); typing it by hand is equivalent to using the control and validated the same way (accepted residual).
- Persistence (accepted residual): the command events are log-only appends that DSH persists at its ordinary checkpoints, not at once. A hard kill of the instance before the next checkpoint can lose a scope change that no later turn followed.
- A fork copies the event prefix, so the scope is inherited and the control shows in the fork. A child Agent's Session renders no control, and the released controller refuses commands there.
- Blank-Session reuse (accepted residual): DSH treats a Session without `turn/start` as blank and reuses it for 「新建」 and the login landing. A scope changed in a new Session before its first message therefore reappears the next time 「新建」 returns to that Session, instead of 「全部」.

The client registers the `conversation.input.left` entry `{ id: 'knowledge-base-scope', order: 100 }`, which reads only `useProjection('kbScope')` and renders nothing for a child Session or a missing view. Its button reads 「知识库：全部」, 「知识库：不检索」 or 「知识库：N 个」 and carries `data-dsh-team-kb-scope` (`all`, `none`, `some`). The popover offers 「全选」 (writes `null`) and 「取消全选」 (writes `[]`), then one checkbox per library from `api/knowledge-base.datasets` with the panel's loading, not-configured, retryable failure and empty states. Unchecking a library under the whole scope writes every listed ID but that one; otherwise a toggle removes or appends that one ID, keeping the order and any selected ID no longer listed (a deleted library, which 15.4 reports as `excluded`). Writes go through `remote.commands.execute(sessionId, '/kb-scope <json>', [])` one at a time: a synchronous in-flight flag disables the actions, and after a saved write they stay disabled until the projection shows the written selection (the same IDs in any order, or the whole scope), the control moves to another Session, or 2 seconds pass, so a quick second change never starts from the stale selection; a failed remote call, an unknown command or an error result shows 「范围保存失败，请重试」, and the button changes only when the projection does. The `conversation.chat.commandview` entry under the key `kb-scope` renders nothing, so the transcript shows no command card. The released outer row element (`callRow`) still remains for each command and may add a few pixels of spacing (accepted residual). The manifest's `dsh.client.inject` therefore also names `@deepseek-ai/dsh-api-remotes`, `@deepseek-ai/dsh-client-ui-conversation` and `@deepseek-ai/dsh-client-ui-chat`, and the client injects `remote` and `remote.commands` as the released plan client does. The arguments carry dataset IDs only, never a RAGFlow address, key, instance token or retrieval parameter.

### Retrieval tool

When available, the host half also registers, through `ctx.inject(['tools', 'sessionProjections', 'agents'], …)`, the global tool `knowledge_base_search`; without those services the panel and the scope control work as before and there is no tool. Child Agents inherit global tools (`tool-subagent` accepts no `toolFilter`), so 综合办公 and 公文与材料写作 both see it; `plugins/office-agents` is unchanged. It is not one of the mutations `permission-tiers` gates, so no tier asks for approval. No client `tool.call.toolview` is registered.

- Parameters are exactly `{ question: string }` (`additionalProperties: false`). `execute` checks the question as the proxy does (non-blank by the same whitespace rule as `keywords`, U+0085 included, at most 4096 UTF-8 bytes) and forwards it untrimmed; anything else returns `invalid-question` without a request. The name, description and parameter description carry no `kb-scope`, 「知识库范围」 or dataset ID: the definition goes to the model with every request.
- **Root resolution.** A Session whose header has no `origin: 'subagent'` is its own root (an employee fork included) and searches its own `kbScope.turn.scope`; its Agent calls the tool inside its turn, so that snapshot is the current turn's. A child Agent never reads its own projection (a child Session's fold reads every library). Instead the host listens to the released `agent/created` (`{ agent, source }`, awaited before the child's queued input is released, so before its first tool call): for a child created with `startup`, a grandchild copies its parent's record, and any other child walks `header.parentSession` through `ctx.agents.get` (at most 16 hops) to the root and records that root's `turn.scope`; `resume` (a new task from the employee or the parent Agent) records the root's current turn the same way; `compact` and `clear` never overwrite (rc.2 announces neither for in-process children). Records live in memory per child Session ID and are deleted on `agent/disposed`.
- **Asynchronous delegation.** Because the child keeps the scope of the turn that created it, a later change of the root's scope or a later turn does not reach it, and it can never widen the scope. Without a record (a child resumed after an instance restart, or created before the plugin loaded), a parent no longer in memory, a missing projection, a `turn` of `null` or more than 16 hops, the tool returns `scope-unavailable` without a request.
- `[]` sends nothing and returns `no-scope`. `null` first lists every library through `GET …/ragflow/datasets` (the panel's request function); an empty list returns `no-datasets` without retrieving, and a failed list returns its result. Otherwise the scope's IDs are used as they are.
- Retrieval is one `POST <platformUrl>/_platform/instance-api/ragflow/retrieval` whose body is exactly `{ question, datasetIds }`, through the same request function as the panel (`Authorization: Bearer <DSH_TEAM_INSTANCE_TOKEN>`, `content-type: application/json`, `redirect: 'manual'`), with its own 25-second deadline through the body, combined with the call's `exec.signal` and the plugin's disposal, and an 8 MiB answer limit. The tool declares `timeoutMs: 60_000` (a list and a retrieval); the Web composition may not enforce it.
- The answer is checked as strictly as the panel's: `ok` needs string `content`, `documentName` and `datasetName` on every chunk and `positions` absent or a non-empty list of 5-number tuples, and both `ok` and `no-results` need a string `excluded` list; anything else is `upstream-error`. A transport failure or cancellation is `unavailable`, the deadline `timeout`. The tool never throws.
- The value is `{ result, chunks?, excluded? }`, `excluded` being the number of skipped libraries, never their IDs. `output.presentationMeta` gives the card `{ result, title, excluded, chunks }` (also persisted as the native `tool/result` `meta`), and `presentResult` shows a generic card from it. The model text and the card share one text: the title, 「有 K 个已选知识库已不可用，已跳过」 when K > 0, then every chunk with 文件 and 所属知识库, 「位置：…」 only when `positions` is present (verbatim, no page number derived), and its content. Only library and file names appear, never a dataset ID, the token or the platform address.

| `result`            | Model text and card title                     |
| ------------------- | --------------------------------------------- |
| `ok`                | 知识库检索：N 条结果 (followed by the chunks) |
| `no-results`        | 知识库中没有找到相关内容                      |
| `no-scope`          | 本轮没有选择知识库，未检索                    |
| `no-datasets`       | 平台上还没有任何知识库，未检索                |
| `scope-unavailable` | 无法确定本轮的检索范围，未检索                |
| `invalid-question`  | 检索问题为空或过长，未检索                    |
| `invalid-request`   | 检索请求无效                                  |
| `not-configured`    | 知识库未配置，请联系管理员                    |
| `timeout`           | 知识库检索超时，请稍后重试                    |
| `unavailable`       | 知识库暂时不可用，请稍后重试                  |
| `upstream-error`    | 知识库返回了异常结果，请稍后重试              |

Logs carry the panel's fixed lines and the result only, never the question, a chunk, a dataset ID, the token or the platform address.

## Config contract

The bundle patch (`cordis.patch.yml`) is exactly one insert row, `{ id: knowledge-base, name: /opt/dsh-team/knowledge-base/index.js }`, without `config` or override rows. The managed overlay (#447) targets that id with `{ id: 'knowledge-base', config: { platformUrl } }` in network mode.

- No platform address is a designed state, not an error: a `config` that is `undefined`, `null` or a plain object without own keys registers no route and publishes `{ available: false }`. This is the state in `published-loopback` mode, where the overlay writes no `knowledge-base` config row; in network mode the overlay always gives `platformUrl` (#447).
- With an address, `config` is exactly `{ platformUrl }`: the string `http://<canonical dotted IPv4>:<port>`, whose last octet is 3 modulo 16 (the instance bridge's +3 platform address, the same rule the generator applies to +2), with a decimal port 1..65535 without leading zeros, and no path (a trailing `/` included), query, fragment or user information.
- Any other shape (an extra or symbol key, a non-string or accessor value, a malformed or non-+3 address, an array or a non-plain object) makes `apply` throw a `TypeError` with a fixed message that does not echo the input, before it touches the host context. The whole plugin then fails to load, which the existing plugin-failure marker checks report, as with a tampered `platform-nav` row.

The row name is an absolute `/opt` path rather than the package name: when the overlay forces the entry on in a profile without its registered copy (a home volume created before stage 2, or one whose copy an employee uninstalled natively), it writes this whole patch, and only the absolute path resolves there, to the root-owned canonical copy; the adjacent manifest still delivers the client half.

## Trusted delivery

Build the user image with all five narrow plugin named contexts:

```sh
docker build -f images/dsh-user/Dockerfile -t dsh-team-user \
  --build-context "zh-locale=$(pwd)/plugins/zh-locale" \
  --build-context "permission-tiers=$(pwd)/plugins/permission-tiers" \
  --build-context "office-agents=$(pwd)/plugins/office-agents" \
  --build-context "platform-nav=$(pwd)/plugins/platform-nav" \
  --build-context "knowledge-base=$(pwd)/plugins/knowledge-base" images/dsh-user
```

The image copies `package.json`, `index.js`, `client.js` and `cordis.patch.yml` to root-owned mode `0444` files in the mode `0555` directory `/opt/dsh-team/knowledge-base/`, outside the employee-writable `/data/home`. The catalog lists it as the manageable item `knowledge-base` (「知识库」) with `imageDefaultEnabled: true`, so `catalog-check.mjs register` copies it into the Web profile as the installed dependency `file:/opt/dsh-team/knowledge-base` and appends it to `dsh.profile.bundles` in catalog order, before the office bundle. The build fails unless the installed DSH satisfies `engines.dsh` and the profile copy equals the canonical copy byte for byte. Its enablement follows only the catalog's three states: `employee` (the default) leaves the employee's plugin-page switch in charge, and the overlay's catalog rows force `forced-on`/`forced-off` (#407).

Legacy home volumes: Docker seeds the profile only into an empty home volume. An employee whose home volume existed before this image has no registered copy and no bundle membership, so in the `employee` state they have no knowledge base until an administrator resets their profile, like the office bundle. `forced-on` loads it on those volumes through the absolute path row.
