# 中文公文与材料

## 职责边界

本 Skill 不改变当前 Agent 的预设职责。综合办公按其原生委派流程交给公文写作完成写作任务；新建所请求的 DOCX 必须实际构造，已有文档修订保留现有编辑工具。可以先提供事实、材料或草稿，也可以在子任务后核验和修正产物，不能以父 Agent 独自生成、子 Agent 仅复制完整 DOCX 代替委派构造。以下清单供公文写作执行，也供综合办公核验真实产物；普通文件操作不因此变成公文写作任务。

## 写作与核验清单

- 先确认文种、用途、主送对象、事项、落款与日期。使用用户提供的材料和模板；没有单位模板时采用通用结构，不声称符合未提供的内部规范。
- 通知包含标题、主送对象、时间地点与具体事项、执行要求、落款和日期；请示明确背景、理由、请求事项与拟办方案；说明按事实、依据和结论组织。
- 区分事实与建议。缺失的必要信息向用户核实或明确标注待确认；不得编造机构、人名、文号、引文、日期或外部核验结果。
- 文字简洁、称谓一致，检查数字、日期、责任主体和附件引用。修订已有材料时保留未要求改变的事实与结构。
- 新建所请求的 DOCX 必须由公文写作调用 `build_docx`：`path` 是当前 Session 工作目录内的新文件路径，`paragraphs` 是有序的 `{text, style?}` 对象数组，`style` 可选 `title`、`heading1`、`heading2`、`normal`。不提供完整 DOCX 字节、来源文件或代码，也不以 bash/Python 生成或复制完整 DOCX 替代该构造操作。父 Agent 提供的事实和草稿可以作为段落内容；此操作证明构造执行，不证明独立创作。
- 输入限 1–64 段，每段最多 4096 个 Unicode 码点，段落文本数组 JSON 编码后最多 32768 个 UTF-8 字节；产物最多 1 MiB。目标父目录须已存在，不允许路径穿越、符号链接或已有目标；已有目标会明确拒绝，不要删除现有材料来绕过新建限制。
- 已有 DOCX 编辑、重新打开与结构检查继续复用 `office-docx` Skill 和现有工具。部署已提供 `/usr/bin/python3` 和 `python-docx`；不联网安装依赖。`build_docx` 同样受人工批准、Auto 审查及 Yolo 的既有权限规则约束，拒绝或取消后不宣称成功。
- 保存后重新打开产物，核对标题、主送对象、正文事项、落款与日期。结构检查不等于视觉版式检查；没有渲染能力时如实说明，不声称检查了分页或字体显示。
- 仅交付真实存在的最终文件；用 `present` 提供文件入口，保留源文件，不把临时检查报告冒充最终文稿。
