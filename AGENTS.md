## Code Canonicality

Same logic must have exactly one implementation in the repo. Version evolution belongs in git history, not in filenames or identifiers.

- Before adding any function, class, module, or file: grep the codebase for an existing implementation. Extend or refactor it; create new only if truly absent.
- Forbidden suffixes for file, class, function, and module names: `_v1`, `_v2`, `_new`, `_old`, `_backup`, `_temp`, `_copy`, `_final`, `_real`, `_improved`, `_refactored`, `_fixed`, `_legacy`, `_deprecated`, and their PascalCase forms on types (`GatewayLegacy`, `AuthV2`).
- Refactor in place: commit the working state, modify the original file, run tests. Never keep an old version alongside the new one — git is the safety net.
- No parallel implementations as a transition. Replace atomically.
- Commented-out code is deleted, not kept. Git remembers.
- Unreferenced exports and dead code paths are debt. Wire them up in the same change or delete them.
- Do not use the repo as a scratchpad: `tmp/`, `scratch/`, `backup/`, `_old/`, `deprecated/`, `archive/`, `wip/` must not appear in commits.
- User-authorized OpenSpec exception (#199): only the managed `archive` component in root-relative `openspec/changes/archive/YYYY-MM-DD-<kebab-change>/<file>` is allowed. The dated change name follows OpenSpec's lowercase alphanumeric, single-hyphen grammar. Other scratchpad components, forbidden suffixes, dot-segment aliases and unrelated staged violations remain rejected. The pattern lives in `constraints.yaml`; both hook entrypoints share one classifier, and `pnpm test:guardrails` proves acceptance and rejection.

## Development Workflow

### Local setup

Run `pnpm install` after clone. It needs Node and pnpm at the versions in `.tool-versions`, plus `hurl`, `shellcheck`, and `gitleaks` on `PATH`.

Python 3 with standard-library `pty`/`termios` support is required for administrator CLI terminal integration verification on POSIX hosts; missing prerequisites fail rather than skip that coverage.

`pnpm dev` builds the web package, then uses the native Node watcher. A missing `.env` is optional: supply required configuration through the environment. When `.env` exists at launch, Node retains its own parsing and inherited-environment precedence; source/import changes still reload the application. Restart `pnpm dev` after creating an env file that was absent at launch. The foreground launcher never creates an empty file or changes `dev:bg`/production startup. `pnpm test:integration platform/test/dev-watch.integration.test.ts` exercises native watch startup/reload and unreadable-input rejection with owned nonsecret process fixtures; real source-main health still requires the configured Docker Engine.

The actual source and built platform entrypoints require a real Docker Unix socket and await reconciliation. `pnpm dev:bg` preflights the configured Engine. `pnpm e2e` instead provisions its own Docker and containerd runtime before main: nonroot Linux, installed `/usr/bin/dockerd`, `/usr/bin/containerd`, `/usr/sbin/ip`, Python3, util-linux `unshare` with PID/mount/network namespace support, and noninteractive sudo are required. Unsupported hosts (including macOS) fail closed; no shared-Engine fallback or image pull is performed. Run only reviewed trusted checkout code with that privilege. Build, main and the complete HTTP smoke client run together on the private namespace's loopback; printed loopback URLs are not host-facing listeners. The scenario remains nonroot and retains health and exact schema/migration ledger checks. CI's default daemon still serves dev-server smoke.

The private runtime uses containerd2.x configuration version3 and requires Docker's `/info` to identify its containerd address and container/plugin namespaces. Docker28.0.4 on hosted CI and29.1.3 on giap-vps have exercised this entrypoint; unknown or incompatible runtime identity fails closed. No daemon upgrade is performed. The supervisor captures two fresh0700 directories: privileged state stays UID0-only, while only the separate socket/temp directory is transferred to the caller. Both remain under the supervisor's cleanup authority, including caller death; no caller-supplied path is adopted. util-linux `unshare --fork` ignores group SIGINT/SIGTERM while waiting, so ordinary command cancellation reaches the owner through stdin EOF rather than bypassing its cleanup.

## Runtime Lifecycle

| Action             | Command           |
| ------------------ | ----------------- |
| Start (background) | `pnpm dev:bg`     |
| Stop               | `pnpm dev:stop`   |
| Status             | `pnpm dev:status` |
| Tail logs          | `pnpm logs`       |

- The dev server listens on `PLATFORM_PORT` (default 8080); health check at `http://127.0.0.1:8080/healthz`. Verify only after the health check passes.
- Never verify against a stale process — restart after dependency, schema, or config changes.
- Never leave orphan dev processes — run `pnpm dev:stop` when done.
- Background start/stop serialize the complete PID-ownership transition with `.run/dev.lock`; concurrent lifecycle commands fail explicitly rather than claiming predecessor readiness. Stop retains `.run/dev.pid` and `.run/dev.stopping` until actual graceful exit; its30s timeout and signal interruption retain ownership and never force-kill to claim completion. Retry stop after work settles. Failed readiness uses the same cleanup and reports only the private log path, not raw secret-bearing output. A leftover lock after an uncatchable shell termination requires operator removal only after confirming no lifecycle command owns it.
- Fresh-data e2e ignores inherited Engine selection and supplies its captured private socket. Docker/containerd storage and process isolation are supplemented by a separate kernel network namespace: unchanged caller identity is rejected before daemon/network mutation, and both daemon memberships are checked before main. Only private loopback is enabled; bridge/firewall flags alone are not isolation. Stdin EOF handles caller loss, and PID/mount containment retires descendants on supervisor death. Shutdown settles scenario, Docker and containerd before removing both captured directories; unconfirmed cleanup fails. `pnpm test:docker platform/test/e2e-engine.docker.test.ts` requires held employee-bridge survival, caller default-bridge identity preservation, namespace/prerequisite/identity/setup failure and process-death cleanup evidence. The read-only smoke suite does not start employees; future image/network/publication coverage needs separate qualification. Dev-server shared-Engine semantics and watcher issue#174 are unchanged.

## Conventions

### Naming

- Files: kebab-case (`managed-config.ts`). Identifiers: camelCase; types and classes PascalCase; constants UPPER_CASE.
- Tests: `<name>.test.ts` next to the source; integration tests `platform/test/<name>.integration.test.ts`; real Docker tests `platform/test/<name>.docker.test.ts` in the VPS-only project.
- Domain concepts use the terms in `openspec/glossary.md`.

### Commit format

- Conventional commits: `<type>(<scope>): <message>`. Types: `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `ci`, `build`, `perf`.
- Scopes: `platform`, `plugins`, `images`, `deploy`, `docs`, `repo`, or a module name.
- Agent-authored commits end with a `Co-Authored-By:` trailer naming the agent.
- Enforced by `commitlint` (`commitlint.config.cjs`).

### Pull requests and branches

- Use `.github/PULL_REQUEST_TEMPLATE.md`. Required sections: Summary, Test plan, Runtime evidence, Risk.
- Trunk-based on `main`; feature branches named `<author>/<short-slug>`; one task = one branch.
- `main` is protected: changes land through a PR on which `All checks passed`, `PR diff size guard`, and `Lockfile-manifest consistency` are green; administrators are not exempt.
- No stacked-PR chains: land dependent PRs sequentially. History rewrites use `--force-with-lease`, never raw `--force`.
- A PR stays under 400 changed lines (lockfiles and snapshots excluded) or carries the `diff-limit-exempt` label with a justification.
- PR event invocations have independent concurrency groups; even repeated label deliveries cannot cancel running checks or replace pending siblings. Superseded PR runs may finish: this trades runner usage for truthful required statuses. Main pushes retain their shared-ref group and no-running-cancellation policy. `pnpm lint:ci` evaluates the delivered workflow; guardrails reject old ref-only, cancel-disabled-only, action-only repeated-label collisions and invalid policies.
- Before merging, inspect the full `gh pr view <PR> --json headRefOid,statusCheckRollup` for the frozen head and all required contexts. `gh pr checks` alone can hide an older same-head cancelled run. A successful sibling does not erase failure; resolve the actual failed/cancelled run and recheck. Never use admin bypass, delete required checks or treat skipped/cancelled dependencies as successful.

## Code Review Self-Check

- Can explain "why this approach" against the nearest obvious alternative; matched existing patterns unless there is a stated reason to diverge.
- Verified the change is made at the correct layer, not by silencing a symptom.
- Ran the narrowest checks covering every changed surface, and they pass on this branch.
- Added or updated tests, and saw the new tests fail before the fix and pass after.
- Checked canonicality: no `_v2` files, no duplicated logic, no dead exports, no scratch directories.
- No new implicit global state; no environment-only behavior left out of `.env.example`.
- Kept the diff focused: no drive-by refactors, no unrelated formatting churn.
- The PR description states intent, approach, test plan, and risk, and says what was not tested.

## Architecture Discipline

- **TDD is required.** Write the failing test first; every production source file has a sibling test (`pnpm lint:tests`). Cadence, test structure, and forbidden shortcuts: `platform/AGENTS.md`.
- **DSH source is never modified.** Customization goes through platform code, DSH plugins, the managed overlay, and the image build (decision D1).
- **Misconfiguration fails loud.** Invalid configuration stops the process at startup; never fall back silently.
- **Routes declare schemas.** Every HTTP route carries a response schema; `schemas/openapi.json` is regenerated with `pnpm contract:write` in the same change.

## Agent Operating Rules

Agents may commit to feature branches, open PRs targeting `main`, run every local check, and propose changes to `AGENTS.md` (human review before merge).

### What agents may not do

- Push to `main`, force-push a shared branch, or use `--no-verify`.
- Modify DSH source, or reset, clean, or check out anything under `resource/`.
- Write to RAGFlow, or to any existing intranet service (RAGFlow, Document Server, model gateway).
- Run destructive container, volume, or database operations against anything but test resources this project created (`dsh-team` prefix), locally or on the verification host (decision D16).
- Upgrade a major dependency version, or change `.github/workflows/`, without flagging it in the PR description.
- Weaken, skip, or delete a test or a gate to get green.

### Secrets handling

- Never read, print, or paste `.env` files or secret values; `.env.example` is the only secrets-adjacent file agents open. Refer to secrets by variable name only.
- Keys never appear in docs, replies, commits, logs, or test fixtures. The RAGFlow key stays in the platform backend — never in a browser or a user shell.

### Evidence requirements

- Success claims need fresh output from the current session: command, exit code, relevant output.
- Verify the world, not the self-report: re-run the command, hit the real endpoint, query the row.
- UI claims need a screenshot and zero new console errors.
- PRs include a `## Runtime evidence` section; "None — review-only change" needs a stated reason.

### Scoped verification

- Select the narrowest check that covers the changed behavior, and report only commands actually run. CI owns the exhaustive run.
- Derive the change list with `pnpm change-scope origin/main`, never from a guessed base.
- Never use pass-with-no-tests or a narrowed include to hide an uncovered file.

### Iteration loop and concurrency

- Max 3 fix-and-recheck cycles per failing check; then stop and report what was tried.
- Checkpoint commit at every green state. One task = one branch.
- Parallel agents use separate git worktrees. Rebase onto `main` before opening or updating a PR.
- Lockfile conflicts are resolved by re-running `pnpm install`, never by hand.

### Debugging CI failures

Classify the failing job (`layer1-fast-checks`, `layer2-unit-tests`, `layer3-integration`, `layer4-anti-drift`, `layer5-secret-scan`, `sast`, `guardrails`), read the first actionable error, reproduce locally with the same `pnpm` script, fix the root cause, re-run that script.

### Incident-to-constraint ratchet

- A non-obvious lesson costing more than 30 minutes becomes a dated entry in `## Important Development Notes`.
- The third incident of the same class becomes a lint rule or a hook, with its rejection case added to `scripts/test-guardrails.sh`.
