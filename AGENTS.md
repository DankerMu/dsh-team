## Code Canonicality

Same logic must have exactly one implementation in the repo. Version evolution belongs in git history, not in filenames or identifiers.

- Before adding any function, class, module, or file: grep the codebase for an existing implementation. Extend or refactor it; create new only if truly absent.
- Forbidden suffixes for file, class, function, and module names: `_v1`, `_v2`, `_new`, `_old`, `_backup`, `_temp`, `_copy`, `_final`, `_real`, `_improved`, `_refactored`, `_fixed`, `_legacy`, `_deprecated`, and their PascalCase forms on types (`GatewayLegacy`, `AuthV2`).
- Refactor in place: commit the working state, modify the original file, run tests. Never keep an old version alongside the new one — git is the safety net.
- No parallel implementations as a transition. Replace atomically.
- Commented-out code is deleted, not kept. Git remembers.
- Unreferenced exports and dead code paths are debt. Wire them up in the same change or delete them.
- Do not use the repo as a scratchpad: `tmp/`, `scratch/`, `backup/`, `_old/`, `deprecated/`, `archive/`, `wip/` must not appear in commits.

### Enforcement

| Rule                         | Enforced by                                                      |
| ---------------------------- | ---------------------------------------------------------------- |
| Forbidden suffixes (paths)   | `.git-hooks/check-naming.sh` (pre-commit hook)                   |

Repository growth therefore does not silently dilute the canary; the repository duplicate-code command, exclusions and threshold are unchanged.

### Environment

- `.env.example` lists the variables (`PLATFORM_HOST`, `PLATFORM_PORT`, `PLATFORM_LOG_LEVEL`, `PLATFORM_DATA_DIR`, `PLATFORM_MANAGED_CONFIG_DIR`, `PLATFORM_PUBLIC_URL`, `PLATFORM_COOKIE_SECURE`, `PLATFORM_TRUSTED_PROXIES`, `PLATFORM_SUBNET_POOL`, `PLATFORM_UPSTREAM_MODE`, `PLATFORM_CONTAINER_NAME`). Copy to `.env` for local runs. Invalid values stop the process at startup; host-run lifecycle development must explicitly select `published-loopback`. Unset `PLATFORM_MANAGED_CONFIG_DIR` defaults to `<dataDir>/managed-config` and is resolved to an absolute path.
- `PLATFORM_SUBNET_POOL` defaults to `172.30.0.0/16` only when absent. Supply a canonical dotted IPv4 network CIDR with zero host bits and prefix `/0` through `/28`, without whitespace. Operators must choose an address pool that does not conflict with host, LAN or existing Docker networks. After migration and before serving, startup compares its geometric `/28` capacity against persisted `maxRunningInstances` (default 60); equality passes, insufficient or malformed pools fail naming `PLATFORM_SUBNET_POOL`. Startup performs no Docker discovery or occupancy subtraction.
- Task10.1 exposes pure `allocateSubnet(pool, occupiedSubnets)` through the orchestrator API: first-fit aligned `/28`, range-overlap exclusion, explicit exhaustion, no hidden reservation. Task10.2 (#45) must fetch fresh IPAM CIDRs from all relevant Docker networks, not only project-labeled networks, and serialize selection with creation. Repeating the same snapshot deliberately returns the same subnet; release/reuse is represented by the next snapshot. No network creation is supplied by task10.1.
- `PLATFORM_UPSTREAM_MODE` defaults to exact `network`; instances publish no host ports and the captured owner attaches the configured `PLATFORM_CONTAINER_NAME` (default `dsh-team-platform`) to each owned instance bridge. The inspected instance IPv4:3080 is the upstream. Platform identity and both endpoint inspect views are verified before use; name/ID changes, foreign endpoints, additional instance networks and publication fail closed. Retirement disconnects only that exact platform endpoint before deleting the confirmed empty bridge, preserving data and sibling/primary networks.
- Readiness-failure cleanup can leave the exact indexed user container stopped and detached after deleting its bridge. Explicit retirement and indexed reconciliation may retire that retained error container only after immutable container/image/name/user and declared bridge-ID checks, no-publication validation, current-row/account fences and independent canonical-name/declared-ID absence confirmation. Missing live attachment is not a reason to reject this verified stopped state; live, foreign or extra attachments and unknown bridge endpoints still fail closed. No orphan discovery or reattachment is implied.
- Confirmed-started compensation revalidates the newly inspected post-stop document before deleting the container: immutable identity and stopped state, no publication, canonical stopped topology and the captured bridge declaration must still agree. A topology/declaration/publication change during stop preserves the stopped container and its endpoints with an explicit unconfirmed-compensation error; a pre-stop validation is not deletion authority.
- Explicit `published-loopback` is only for a platform process running directly on the Docker host: instance3080 publishes to127.0.0.1 at a random host port and no platform attachment occurs. It does not satisfy the deployment no-host-port requirement. Both configuration fields are validated before listening without contacting Docker; every lifecycle operation uses the owner's captured transport.
- Task10.4 (#47) extends explicit awaited `owner.reconcile()`: after platform recreation, a fresh owner resolves the configured name to the new immutable ID; a live owner never resets its pin. Only missing configured-platform membership on an otherwise verified active, running, unexpired indexed survivor is repaired, with fresh identity/topology/upstream and complete row/account fences before acceptance. Successful recovery preserves containers, credentials, rows and audits. Confirmed attachment failure uses guarded retirement and atomically records safe `error`/null runtime identity with the existing error-reason stop audit; repeated stop/reconcile preserve that terminal error, and fresh start may retry. Unknown or changed resources and failed cleanup remain explicit failures, not successful retirement evidence.
- Reconciliation may delete exact canonical labelled bridge `/28` orphan candidates, including those without an account/index, only after fresh exact404 absence of both canonical and any distinct indexed user container, unchanged row/account and captured network identity/subnet, and freshly verified empty or configured-platform-only endpoints. It disconnects only the verified platform endpoint with `Force:false`, confirms emptiness and exact-ID deletion, and preserves data, sibling/primary networks and unrelated resources. Cleanup uses the existing per-user queue, respects owner-local unknown-create quarantine and failed indexed reconciliation, and retains bounded submitted-mutation settlement despite cancellation. Published-loopback performs no platform attachment; neither mode uses global prune or automatic startup reconciliation wiring.
- No secret is needed by the current skeleton. Model and RAGFlow keys arrive later through environment variables only.
- Gateway admission reserves `/healthz`, `/_platform` and `/_platform/` descendants; unknown reserved paths stay platform404. Other paths require a current active platform session. Anonymous GET/HEAD accepting explicit positive-quality `text/html` redirects to `/_platform/login`; other anonymous requests and upgrades receive401. Task11.2 adds optional `buildApp(config, database, logDestination, resolveUpstream)` injection: the synchronous resolver receives only the authenticated user ID and returns the trusted HTTP host/port/DSH-cookie pair. HTTP forwarding strips client Cookie and hop-by-hop headers before trusted Cookie/Host injection, strips response Set-Cookie and trailers, and pipes without body parsing. Missing destinations still return503; main has no resolver until task12.1. WebSocket forwarding and login rendering remain later tasks. Platform mutation guards are unchanged; upstream errors are sanitized and paired streams close on failure/cancellation.

### Administrator deployment command

Run `pnpm --silent cli admin create <email>` from source, or `node platform/dist/cli.js admin create <email>` after building. The source wrapper requires `--silent`: plain `pnpm cli` prints its lifecycle command banner before Node validates arguments and can disclose rejected password arguments. Never supply a password in arguments; silence prevents wrapper disclosure, not shell-history or process-argument exposure. Export the existing configuration, including required `PLATFORM_PUBLIC_URL` and the intended `PLATFORM_DATA_DIR`; the CLI does not load `.env` itself. Interactive input **and** output are mandatory, and password arguments/environment input are not supported.

New accounts receive an active administrator identity after two matching hidden password entries. Existing accounts offer password reset with default **no**: promotion otherwise preserves password, status (including disabled), identity, creation time, and sessions. An existing administrator without reset is a no-op. Reset revokes all target sessions and records the actual promotion/reset events atomically; it does not issue a CLI session or enable disabled accounts. A concurrent target change rejects the operation; rerun rather than overwrite the newer account.

The command restores terminal mode and releases its database/listeners on completion or cancellation. Success is reported only after account/session/audit commit. Administrator web-page availability remains owned by the later administrator UI issue.

### Trusted Docker verification

`pnpm check` and `pnpm test:integration` never start Docker. Only the trusted parent session runs `pnpm test:docker` on giap-vps (Ubuntu 24.04/Linux amd64), after full review of the exact commit. Install Node 24.13.1 and pnpm 10.34.6 from `.tool-versions` below ubuntu's home, verify executable paths and versions, and leave system binaries/packages unchanged. Missing Docker/daemon/tool prerequisites fail, not skip.

The resource-OOM verification also requires trusted host read-only kernel-journal access through noninteractive `/usr/bin/sudo -n /usr/bin/journalctl` on the current boot. The fallback queries only the exact owned systemd Docker `oom_memcg` and the physical-pressure time window, with a 5s process deadline and 64KiB output cap; records are projected to typed causal fields, never raw journal messages/errors. Missing privileges/records or malformed, global, foreign or out-of-window evidence cannot substitute for OOM proof. This is a verification-host prerequisite, not a production dependency or permission to modify host controls; Docker OOM flags and child cgroup-counter proof remain valid paths.

The Docker suite builds the user-image Dockerfile with the `images/dsh-user` primary directory context and the explicit BuildKit named context `zh-locale=<repo>/plugins/zh-locale` (no repository-root files or secrets), and runs each probe from its captured image ID. No user override or runtime installer is allowed. Its test-first case must fail on the pre-Python image before the package change is admitted.

The profile-seed case uses a fresh invocation-owned Docker named state volume at `/data/home`, with ordinary first-mount copy-up and no manual copy. Plugin delivery does not activate the plugin or rewrite mutable profile policy; managed overlays remain a later task. The reviewed test-first candidate must fail on missing/nonmatching profile contents before the image capability is admitted. Each invocation labels unique `dsh-team-test-*` image/container/volume targets. Cleanup checks exact ownership and removes all invocation-owned containers before the volume and image on success, assertion failure or partial creation; cleanup failures fail verification and preserve output. No prune, host bind mounts, ports, privileged flags or model/service credentials.

The task7.4 Web startup case reuses that lifecycle with a handwritten readonly `0.0.0.0:3080` overlay, two distinct labeled named volumes, the absolute shipped seccomp file and Docker-assigned loopback-only publication. Logs and launch tokens remain in memory and never enter reports, including failures. Docker-free adverse-observation tests qualify missing-token, exit, deadline, HTTP200, process and mount/security rejection through `pnpm test:integration`; trusted exact-head `pnpm test:docker` still requires independent success/failure cleanup inventories and unrelated sentinels. ## Conventions

### Naming

- Files: kebab-case (`managed-config.ts`). Identifiers: camelCase; types and classes PascalCase; constants UPPER_CASE.
- Tests: `<name>.test.ts` next to the source; integration tests `platform/test/<name>.integration.test.ts`; real Docker tests `platform/test/<name>.docker.test.ts` in the VPS-only project.
- Domain concepts use the terms in `openspec/glossary.md`.

### Commit format

- Conventional commits: `<type>(<scope>): <message>`. Types: `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `ci`, `build`, `perf`.
- Scopes: `platform`, `plugins`, `images`, `deploy`, `docs`, `repo`, or a module name.
- Agent-authored commits end with a `Co-Authored-By:` trailer naming the agent.
- Enforced by `commitlint` (`commitlint.config.cjs`).

### Pull requests and branches

- Use `.github/PULL_REQUEST_TEMPLATE.md`. Required sections: Summary, Test plan, Runtime evidence, Risk.
- Trunk-based on `main`; feature branches named `<author>/<short-slug>`; one task = one branch.
- `main` is protected: changes land through a PR on which `All checks passed`, `PR diff size guard`, and `Lockfile-manifest consistency` are green; administrators are not exempt.
- No stacked-PR chains: land dependent PRs sequentially. History rewrites use `--force-with-lease`, never raw `--force`.
- A PR stays under 400 changed lines (lockfiles and snapshots excluded) or carries the `diff-limit-exempt` label with a justification.

- Can explain "why this approach" against the nearest obvious alternative; matched existing patterns unless there is a stated reason to diverge.
- Verified the change is made at the correct layer, not by silencing a symptom.

## Architecture Discipline

- **TDD is required.** Write the failing test first; every production source file has a sibling test (`pnpm lint:tests`). Cadence, test structure, and forbidden shortcuts: `platform/AGENTS.md`.
- **DSH source is never modified.** Customization goes through platform code, DSH plugins, the managed overlay, and the image build (decision D1).
- **Misconfiguration fails loud.** Invalid configuration stops the process at startup; never fall back silently.
- **Routes declare schemas.** Every HTTP route carries a response schema; `schemas/openapi.json` is regenerated with `pnpm contract:write` in the same change.

| `images/dsh-user/`           | user image, bundled plugins and build-time patches     | Human review of every line |

## Observability

- Server code logs through the Fastify (pino) logger configured in `platform/src/app.ts`: JSON lines, level from `PLATFORM_LOG_LEVEL`.
- `console.*` is rejected by the ESLint rule `no-console` (pre-commit and CI).
- Redaction is part of the logger configuration: authorization and cookie headers, and any `password`, `token`, or `apiKey` field. Add the path in the same change that introduces a new secret-bearing field.
- Never log passwords, keys, launch tokens, DSH cookies, or conversation content (baseline F6).
- Tracing and metrics are deferred until the single-server deployment shows a need.

## Agent Operating Rules

Agents may commit to feature branches, open PRs targeting `main`, run every local check, and propose changes to `AGENTS.md` (human review before merge).

### What agents may not do

- Push to `main`, force-push a shared branch, or use `--no-verify`.
- Modify DSH source, or reset, clean, or check out anything under `resource/`.
- Write to RAGFlow, or to any existing intranet service (RAGFlow, Document Server, model gateway).
- Run destructive container, volume, or database operations against anything but test resources this project created (`dsh-team` prefix), locally or on the verification host (decision D16).
- Upgrade a major dependency version, or change `.github/workflows/`, without flagging it in the PR description.
- Weaken, skip, or delete a test or a gate to get green.

### Secrets handling

- Never read, print, or paste `.env` files or secret values; `.env.example` is the only secrets-adjacent file agents open. Refer to secrets by variable name only.
- Keys never appear in docs, replies, commits, logs, or test fixtures. The RAGFlow key stays in the platform backend — never in a browser or a user shell.

### Evidence requirements

- Success claims need fresh output from the current session: command, exit code, relevant output.
- Verify the world, not the self-report: re-run the command, hit the real endpoint, query the row.
- UI claims need a screenshot and zero new console errors.
- PRs include a `## Runtime evidence` section; "None — review-only change" needs a stated reason.

### Scoped verification

- Select the narrowest check that covers the changed behavior, and report only commands actually run. CI owns the exhaustive run.
- Derive the change list with `pnpm change-scope origin/main`, never from a guessed base.
- Never use pass-with-no-tests or a narrowed include to hide an uncovered file.

### Iteration loop and concurrency

- Max 3 fix-and-recheck cycles per failing check; then stop and report what was tried.
- Checkpoint commit at every green state. One task = one branch.
- Parallel agents use separate git worktrees. Rebase onto `main` before opening or updating a PR.
- Lockfile conflicts are resolved by re-running `pnpm install`, never by hand.

### Debugging CI failures

Classify the failing job (`layer1-fast-checks`, `layer2-unit-tests`, `layer3-integration`, `layer4-anti-drift`, `layer5-secret-scan`, `sast`, `guardrails`), read the first actionable error, reproduce locally with the same `pnpm` script, fix the root cause, re-run that script.

### Incident-to-constraint ratchet

- A non-obvious lesson costing more than 30 minutes becomes a dated entry in `## Important Development Notes`.
- The third incident of the same class becomes a lint rule or a hook, with its rejection case added to `scripts/test-guardrails.sh`.

## Enforcement Index

Strictness profile: **L3** (see `constraints.yaml`). Levels: `advice` < `review-only` < `warn` < `block` < `gate`. Anything below `warn` is a human promise, not a machine check.

### Known blind spots (handed to review)

- Coverage gate: proves lines ran, not that assertions are meaningful — review checks test strength.
- Test pairing: proves a test file exists, not that it was written first or tests the right behavior.
- Contract snapshot: catches drift in routes that declare a schema, never routes without one.
- Pre-commit hooks are local and skippable; CI and branch protection are the authoritative layer.
- Claude Code write-time hooks are not installed: `.claude/` is untracked local tooling.
