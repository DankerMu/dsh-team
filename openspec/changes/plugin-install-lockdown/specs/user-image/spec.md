## ADDED Requirements

### Requirement: 插件页没有安装和卸载入口

用户镜像构建时 MUST 给全局安装的 `@deepseek-ai/dsh-client-ui-plugin-manager` 的 `lib/client.js` 打补丁，删去以下两处，并保留其余一切行为：

- 「添加插件」按钮；
- 插件详情页的卸载按钮。

保留的行为包括：

- 插件开关和 bundle 开关；
- `plugins.item` 中的配置卡片；
- 刷新和详情。

补丁 MUST 在以下任一情况下让构建失败，且不写文件：

- DSH 版本不是 `0.2.0-rc.2`；
- 全局模块中该包不是恰好一份，或这份的版本不是 `0.2.0-rc.2`；
- 输入文件的 SHA-256 不是评审过的值；
- 补丁结果的 SHA-256 不是评审过的值。

补好的文件 MUST 归 root 所有，普通用户不可写。补丁脚本 MUST NOT 留在镜像文件系统中。该补丁 MUST NOT 修改 `/data/home` 下任何文件，也 MUST NOT 修改配置目录的初始副本。

员工从终端执行 `dsh plugin add`，或直接写 profile，属于已接受的残留（D12），不在本要求范围内。

#### Scenario: 插件页只剩开关

- **WHEN** 员工 profile 的 `dependencies` 含有镜像已带的 `@dsh-team/office-agents`（插件页在「mine」分组中显示它，且没有问题标记），员工在真实 DSH 中打开侧栏插件页（同一工具栏的刷新按钮可见），然后进入它的详情
- **THEN** 页面上没有「添加插件」按钮，详情里没有卸载按钮；它的开关存在且可用
- **AND** 把它关掉再打开，每次重新加载页面后开关状态与操作一致；浏览器没有意外的控制台错误

#### Scenario: 镜像中的文件是补过的

- **WHEN** 检查构建出的用户镜像
- **THEN** 该包的 `lib/client.js` 的 SHA-256 等于评审过的补丁后值，文件归 root 所有、uid1001 不可写，镜像中没有补丁脚本

#### Scenario: 版本或内容漂移时构建失败

- **WHEN** 补丁脚本遇到不同的 DSH 版本、多份或零份已安装副本、不同的插件页版本，或不同的输入哈希
- **THEN** 脚本以非零状态退出，目标文件逐字节不变
