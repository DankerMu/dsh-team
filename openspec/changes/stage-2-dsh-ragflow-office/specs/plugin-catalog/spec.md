## Purpose

预装插件目录与部署形态配置：管理员在后台为每个预装插件和 bundle 选择员工自选、强制开或强制关，配置插件安装源、仓库探测和联网工具；员工插件页为每个预装项提供开关，DSH 自带的安装、更新、卸载入口保留。

## ADDED Requirements

### Requirement: 预装目录有唯一来源

预装项是镜像构建在 DSH 发行包之外额外加入的仓库插件、第三方全局包和办公 Agent bundle；DSH 发行包自带的 bundle 不是预装项，不在目录内。预装项的清单 MUST 只有一份来源，同时决定用户镜像预装的内容和后台列出的条目。每个条目 MUST 有稳定的标识、包名、中文名、类别（受管必启项或可管理项）和镜像默认启用状态。镜像预装内容与清单在任一方向不一致时，用户镜像构建 MUST 失败。

#### Scenario: 后台列表与镜像一致

- **WHEN** 管理员打开插件目录页
- **THEN** 列出的条目与用户镜像实际预装的插件和 bundle 完全一致，名称为中文

#### Scenario: DSH 自带的 bundle 不在目录中

- **WHEN** 管理员打开插件目录页
- **THEN** 列表中没有 DSH 发行包自带的 bundle，只有镜像额外加入的预装项

#### Scenario: 清单与镜像不一致时构建失败

- **WHEN** 清单中有一个条目，镜像构建没有预装它
- **THEN** 用户镜像构建失败并指出不一致的条目

### Requirement: 受管必启项固定开启

平台入口、权限档、中文界面和 Office 提示是受管必启项。它们 MUST 在后台目录页和员工插件页中显示，状态固定为 `forced-on` 并锁定；管理员 MUST NOT 能修改它们的状态，员工 MUST NOT 能关闭它们。

#### Scenario: 必启项在员工侧锁定开启

- **WHEN** 新员工打开插件页
- **THEN** 平台入口、权限档、中文界面和 Office 提示四张卡片都显示为开启且锁定，标明「由管理员设定」

#### Scenario: 后台不能改必启项

- **WHEN** 管理员提交把任一受管必启项设为 `employee` 或 `forced-off` 的保存请求
- **THEN** 平台返回 400，设置和审计都不变

### Requirement: 预装项三种管理状态

每个可管理项 MUST 处于且只处于一种管理状态，机器取值为 `employee`（员工自选）、`forced-on`（强制开）、`forced-off`（强制关），初始为 `employee`。`employee` 时，员工插件页的开关可用，默认值来自镜像。`forced-on` 或 `forced-off` 时，该项在员工实例中 MUST 处于对应的启用状态，员工插件页显示为锁定且员工不能更改。状态变更 MUST 在该员工实例下次启动时生效。ONLYOFFICE 例外：本次启动 Office 不可用时，它 MUST 在该实例中停用，不论目录状态，后台目录页 MUST 显示该原因。

#### Scenario: 强制关的项员工打不开

- **WHEN** 管理员把「知识库」设为 `forced-off`，员工的实例之后重新启动
- **THEN** 员工插件页中「知识库」显示为关闭且锁定，员工无法打开

#### Scenario: 强制开的项员工关不掉

- **WHEN** 管理员把「公文与材料写作」所在的 bundle 设为 `forced-on`，员工实例重新启动
- **THEN** 该 bundle 显示为开启且锁定，员工无法关闭

#### Scenario: 员工自选的项可以切换

- **WHEN** 某项为 `employee`，员工在插件页关闭它
- **THEN** 该项被关闭，管理员的设置不变，其他员工不受影响

#### Scenario: Office 不可用时 ONLYOFFICE 停用

- **WHEN** ONLYOFFICE 为 `forced-on`，部署没有配置 Document Server，员工实例启动
- **THEN** 该实例中 ONLYOFFICE 处于停用，后台目录页在 ONLYOFFICE 一项旁显示 Office 不可用的原因

#### Scenario: 运行中的实例不立即变化

- **WHEN** 管理员修改某项状态时员工实例正在运行
- **THEN** 该实例在停止前保持原状态，下次启动后才按新状态生效

### Requirement: 员工插件页每个预装项都有开关

员工插件页 MUST 为每个预装插件和 bundle 显示一张带开关的卡片，包括办公 Agent bundle。卡片 MUST 标明当前状态，强制的项标明「由管理员设定」。

#### Scenario: 全部预装项可见

- **WHEN** 新员工首次打开插件页
- **THEN** 清单中的每个预装项都有一张卡片，并显示开关状态

### Requirement: 安装入口保留并使用管理员配置的安装源

DSH 自带的添加插件、更新、卸载入口 MUST 保留，员工和 Agent 可以安装其他插件。插件安装使用的 npm 源列表和是否开启仓库探测 MUST 由管理员在后台配置，经覆盖层下发，员工不能修改；变更在实例下次启动时生效。两项的初始值 MUST 等于 DSH 0.2.1-rc.2 的默认值：默认公共源列表、探测开启。仓库探测关闭时，实例 MUST NOT 主动访问公共插件仓库。

#### Scenario: 联网部署可以安装插件

- **WHEN** 管理员保留初始的默认公共源，员工在插件页添加一个公共插件
- **THEN** 插件安装成功并出现在员工插件页

#### Scenario: 从管理员配置的源安装

- **WHEN** 管理员把安装源设为一个可达的 npm 源，员工实例重启后在插件页添加该源上的一个插件
- **THEN** 安装请求只发往该源，插件安装成功并出现在员工插件页

#### Scenario: 内网部署关闭仓库探测

- **WHEN** 管理员关闭仓库探测并把安装源指向内网镜像，员工实例重启
- **THEN** 实例对外的请求中没有发往公共插件仓库的探测，安装请求只发往内网镜像

#### Scenario: 员工不能改安装源

- **WHEN** 员工在 DSH 设置中查看插件安装源
- **THEN** 该设置显示为受管锁定，值为管理员配置的源列表

### Requirement: 联网工具由管理员开关

联网搜索和抓取工具 MUST 默认对所有 Agent 关闭。管理员可以在后台打开；打开后在实例下次启动时对所有 Agent 生效，关闭同理。

#### Scenario: 默认没有联网工具

- **WHEN** 管理员没有修改过联网工具开关，员工新建 Session
- **THEN** 任何 Agent 的可用工具中都没有联网搜索和抓取

#### Scenario: 打开后下次启动可用

- **WHEN** 管理员打开联网工具，员工实例重新启动
- **THEN** Agent 的可用工具中出现联网搜索和抓取
