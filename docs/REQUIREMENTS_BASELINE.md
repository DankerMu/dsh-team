# DSH 企业多用户办公平台：需求基线

日期：2026-10-03。本文是开发的需求依据，取代对话中的零散决定。

- 原始任务书：`docs/DSH_Enterprise_Requirements_Standalone.md`（下称“任务书”），不修改。
- 事实依据：`docs/DSH_Enterprise_Architecture_Analysis.md`（下称“分析”）。
- 冲突时的优先级：本文 > 任务书。本文没有提到的条目，以任务书为准。

## 1. 产品定位

几十名内部员工通过同一个网页入口，各自使用一个隔离的 DSH 实例完成行政办公任务：自由对话、调用内置办公 Agent、检索所选的 RAGFlow 知识库、生成和在线编辑个人工作文件。完全内网运行。

## 2. 已定事项

以下由项目方在阶段 0 拍板，不再重新确认。

| 编号 | 事项 | 决定 |
|---|---|---|
| D1 | 主底座 | 新建薄管理层（平台）+ DSH 插件；DSH 源码不改 |
| D2 | 平台技术栈 | Node/TypeScript + SQLite，代码放本仓库；`resource/` 下四个上游仓库只作参考 |
| D3 | 部署 | 单台 Linux（浪潮 5486M6，amd64，56 核，500G，32T，Ubuntu 22.04）+ Docker；Docker socket 只给平台 |
| D4 | 账号 | 员工用邮箱和自设密码自助注册，注册即可用；无审批、无邮箱域名限制、无数量上限。管理员事后管理（禁用、重置密码、查看实例） |
| D5 | 实例 | 每用户一个容器；登录时按需启动，空闲后停止（默认 30 分钟，后台可调） |
| D6 | 模型 | 管理员在后台统一配置地址、密钥、可用模型、默认模型；员工只能在已配置模型中切换 |
| D7 | 模型密钥 | 全员共用一把，以环境变量注入各用户容器。接受员工可通过 Agent 读出 |
| D8 | 权限模式 | 三档：人工批准、Auto（DSH 的 Auto review）、Yolo（完全权限、不询问）。员工按 Session 自由切换 |
| D9 | 插件 | 批准的插件全部预装进镜像，员工只能开关，不能安装 |
| D10 | 新 Session 知识库 | 默认全选，对话区显示当前范围 |
| D11 | ONLYOFFICE | 随项目部署社区版 Document Server 9.4.0；接受 20 个并发连接上限，满员时界面提示 |
| D12 | 终端 | 员工界面的终端入口不隐藏，保持可展开折叠 |
| D13 | 字体 | 使用 `assets/fonts/` 下的仿宋_GB2312、楷体_GB2312、方正小标宋简体、黑体、思源黑体 SC；项目方确认均已授权 |
| D14 | 办公 Agent 参考 | 不依赖 Workbody / WorkBuddy 资料，按分析第 4 节的十个 Agent 定稿 |
| D15 | 仓库 | `DankerMu/dsh-team`，公开（2026-10-03 由私有改为公开，以启用分支保护），商业付费条款；字体不入库，由离线交付包携带 |
| D16 | 阶段 1 沙箱验证主机 | 开发期用项目方的 VPS（amd64，Ubuntu 24.04，Docker 29）验证 shell 沙箱并产出 seccomp 配置；只创建带 `dsh-team` 前缀的镜像和容器，用完删除。目标机 Ubuntu 22.04 上的最终确认由项目方执行探测脚本（2026-10-03） |
| D17 | 传输 | 平台只讲 HTTP；对外地址和“cookie 仅在 HTTPS 下发送”是配置项，TLS 由前置反向代理可选提供；不交付证书管理（2026-10-03） |
| D18 | 首个管理员 | 部署时执行一条命令创建，交互输入密码；同一命令可把已有账号提升为管理员（2026-10-03） |
| D19 | SQLite 驱动 | better-sqlite3（2026-10-03） |
| D20 | 密码规则 | 至少 6 位，无复杂度要求（内网，项目方接受弱密码）（2026-10-03） |
| D21 | 平台会话 | 7 天滑动续期；禁用账号、管理员重置密码、用户改密码立即作废该用户全部平台会话；允许多个浏览器同时登录同一账号（2026-10-03） |
| D22 | 资源上限 | 单实例 2 核、4G 内存；同时运行的实例最多 60 个；三项后台可调。满员时新登录的用户看到“当前使用人数已满，请稍后再试”，不停止他人的实例（2026-10-03） |
| D23 | 默认权限档 | Yolo；管理员可在后台改，员工每个 Session 可切换（2026-10-03） |

## 3. 相对任务书的偏离

| 任务书 | 本基线 | 原因 |
|---|---|---|
| 第六节：管理员创建账号，不需要公众注册 | D4 自助开放注册 | 项目方决定 |
| 第七节：实例调用凭据受限、可撤销；不向用户可任意读取的配置下发长期密钥 | D7 共用密钥直接注入 | 项目方决定；内网环境，密钥只能调模型 |
| 验收 13：凭据不暴露于浏览器、日志或用户可任意读取的管理配置 | 改为：凭据不暴露于浏览器和日志。模型密钥在用户容器内可读，属已接受的取舍 | 由 D7 推出 |
| 未提及权限模式 | D8 三档可切，含 Yolo | 项目方决定 |

RAGFlow 密钥不适用 D7：任务书 9.4 是固定要求，密钥留在平台，用户容器只调平台的只读代理。

## 5. 功能需求

每条标注来源：任务书章节，或本基线的决定编号。

### 5.1 账号与管理后台

- F1 邮箱加密码自助注册和登录（D4）。密码至少 6 位（D20），用 scrypt 加盐存储。
- F2 角色分管理员和普通员工。首个管理员由部署时初始化。
- F3 管理员可禁用、启用账号，重置密码。禁用必须立即断开该用户的全部长连接并停止其实例，不只是阻止下次登录（任务书六）。
- F4 后台页面：账号、实例状态、模型配置、RAGFlow 连接、插件目录、Agent 目录、审计日志（任务书六）。
- F5 后台不提供浏览员工私有文件和对话的功能（任务书六）。
- F6 审计记录登录、注册、管理操作、实例生命周期事件；不记录对话内容、文档内容、密码和密钥（任务书六）。
- F7 管理员可对单个实例执行“重启”和“重置实例配置”（D8 带来：Yolo 档下用户配置可能被写坏导致实例起不来）。

### 5.2 实例与路由

- F8 每用户一个容器，两个持久卷：DSH 状态目录和工作目录（任务书五）。
- F9 网关按登录会话把 HTTP、WebSocket、上传下载、插件路由转发到该用户的容器。不接受客户端提交的任何实例标识（任务书五）。
- F10 用户容器不发布宿主端口，不挂 Docker socket，不持有平台管理密钥和 RAGFlow 密钥（任务书五）。
- F11 用户容器之间网络不互通；只有网关和 Document Server 能访问用户容器（任务书五；分析 3.5 的实测显示同网络下互相可达）。
- F12 每个容器有唯一主机名（分析 3.5：Office 文档 key 依赖主机名）。
- F13 按需启动、空闲停止（D5）。有运行中任务、打开的 Office 编辑器或活动连接时不回收（任务书五）。
- F14 实例停止或重建后文件、Session、设置恢复（任务书五）。运行中任务不承诺断点续跑。
- F15 新实例预置一个指向工作目录的工作区，员工登录后可直接对话（分析 3.6）。
- F16 每个容器设置 CPU、内存上限（任务书五）。

### 5.3 模型

- F17 后台配置地址、密钥、模型清单、默认模型，写入每个实例的只读受管配置；模型部分对所有实例相同（D6）。
- F18 员工不能通过自己的设置覆盖受管配置（任务书七；分析 3.6 已实测）。
- F19 模型不可用时明确报错，不回退到任何其他模型（任务书七）。
- F20 配置变更在实例下次启动时生效；后台可对指定实例或全部实例执行重启。

### 5.4 办公 Agent

- F21 交付十个办公 Agent（D14；任务书四）：综合办公、公文与材料写作、材料校对、会议纪要、工作总结与报告、制度与知识检索、表格与数据分析、演示文稿、会务与活动方案、文件整理。
- F22 默认是综合办公。员工可在新会话时手动指定专业 Agent；自然语言任务可由综合办公委派给专业能力。两种方式都必须真实生效。
- F23 每个 Agent 有稳定标识、中文名、职责、指令、关联 Skills、允许的工具、版本、启用状态，以及一个可执行的验收任务。
- F24 所有 Agent 去掉联网搜索和抓取工具（任务书十一）。
- F25 子 Agent 继承当前 Session 的知识库选择，不能扩大范围（任务书 4.2）。

### 5.5 RAGFlow

- F26 平台提供只读代理，只有四个接口：知识库列表、库内文件列表、限定范围的检索、版本查询。不提供任何写接口，不做通用转发（任务书九）。
- F27 插件页面只读展示知识库名称和库内文件名列表，支持按名称搜索、文件名筛选、分页、刷新。区分加载中、空库、无匹配、请求失败（任务书 9.2）。
- F28 按 Session 多选知识库，支持全选和取消全选；选择与浏览互不联动；刷新和重开后恢复；不影响其他 Session 和其他用户（任务书 9.3）。
- F29 新 Session 默认全选（D10）。员工取消全部后不检索。
- F30 每次提交任务时固定本轮的检索范围；之后的修改只影响后续任务（任务书 9.3）。
- F31 检索前剔除已不存在的知识库并提示员工；剩余为空则不检索。任何情况下都不退回全库（任务书 9.3；分析 3.4：有一个无效 ID 时 RAGFlow 整个请求失败）。
- F32 检索结果显示真实的片段、文件名和所属知识库；页码和位置只在接口有值时显示（任务书 9.4）。
- F33 代理校验每个返回片段属于请求的知识库集合。
- F34 无结果、超时、配置错误、服务中断分别提示；RAGFlow 不可用不影响工作台其他功能（任务书 9.4）。业务错误按响应体 `code` 判断，不能只看 HTTP 状态。

### 5.6 文件与 Office

- F35 工作目录文件的浏览、上传、下载（任务书十；侧栏插件已有）。
- F36 HTML 预览使用受限渲染；“关闭 HTML 预览沙箱”的设置由受管配置钉死为关闭（任务书 10.1；分析 3.5）。
- F37 DOCX、XLSX、PPTX 在线编辑，保存写回原文件（任务书十）。旧 DOC、XLS、PPT 只读预览，不可编辑。
- F38 人工保存后，Agent 读取到的是最新内容（任务书 10.2）。
- F39 文档标识、取文件地址、保存回调都绑定到正确的用户和文件；两个用户的同名文件互不串写（任务书 10.2）。
- F40 人机同时写同一文件时后写覆盖，界面提示：“请勿在 AI 修改此文件时同时编辑；人工修改保存完成后，再让 AI 继续处理。”不做锁和合并（任务书 10.3）。
- F41 Document Server 加载 D13 的字体。
- F42 达到 20 连接上限时明确提示（D11）。

### 5.7 权限模式与界面

- F43 三档权限按 D8 提供；默认档位由管理员在后台设定。
- F44 界面中文；首次进入不出现上游的预览版公告。
- F45 终端入口保留（D12）。
- F46 插件页只显示批准的插件和开关，不出现安装入口（D9）。

### 5.8 离线交付

- F47 全部组件以镜像归档交付，运行时不访问公网；遥测、联网工具、插件安装源全部关闭（任务书十一）。
- F48 提供安装、升级、回滚、备份恢复的步骤和脚本。

## 6. 范围外

同任务书第十三节。另外明确不做：注册审批、邮箱验证、邮箱域名限制、按用户授权权限档位、每用户独立模型密钥、平台模型代理、逐库检索合并（列为可调项）。

## 7. 验收

沿用任务书第十五节的 14 条，以下三条按本基线调整：

- 验收 3：内容不变。工具调用部分在开发环境用 `deepseek-v4.1-flash` 验证，生产环境用 `qwen3.6` 重新验证；“无公网环境下仍可完成任务”部分开发环境验证不了（开发模型走公网），在阶段 3 的离线交付里验证。
- 验收 13：改为“账号禁用和配置停用按策略失效，故障可排查，凭据不暴露于浏览器和日志”。
- 验收 14：并发容量在目标服务器上测量。
