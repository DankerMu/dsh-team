# Platform web pages

Behaviour contracts of the browser pages served under `/_platform/` and how `pnpm test:ui` verifies them.

Moved verbatim from the root `AGENTS.md`; normative behaviour lives in the OpenSpec specs (`openspec/specs/`, `openspec/changes/`). Keep this file current in the same change as the code it describes.

## Static delivery and page behaviour

`pnpm dev`, `pnpm dev:bg`, `pnpm build`, `pnpm test:integration` and `pnpm test:ui` establish a fresh web build. Run `pnpm dev:web` alongside the platform to watch/rebuild those same-origin artifacts; it does not start a second HTTP server. Production startup rejects a missing or unreadable web build before listening. Static delivery declares `/_platform/login`, `/_platform/register`, `/_platform/account`, `/_platform/wait`, `/_platform/admin`, `/_platform/admin/instances`, `/_platform/admin/audit`, `/_platform/admin/models`, `/_platform/admin/runtime`, `/_platform/admin/plugins`, `/_platform/admin/knowledge-base`, `/_platform/admin/office` and `/_platform/assets/*`; unknown pages and APIs retain404, without an SPA fallback.

Install the pinned verification browser explicitly with `pnpm test:ui:install` after `pnpm install`. The UI suite owns its listener and isolated SQLite database through `buildApp`, does not reconcile Docker, and retains screenshots under `reports/platform-ui/`. Browser installation/downloads are local/CI verification prerequisites, never production runtime dependencies. The shared account form submits same-origin JSON to the existing login or registration endpoint, displays pending/Chinese rejection feedback, and navigates exactly once only after the matching success status (login200, registration201), with every response body consumed first. Login, registration and logout then clear origin storage, IndexedDB, Service Workers, CacheStorage and script-visible cookies best-effort before that single navigation; password change does not clear. Registration and every login, administrator included, land on `/` with no further request (#365 reverses the #358 administrator landing); an administrator's first entry therefore starts their own instance and uses one running slot. The gateway owns stopped-instance redirection; neither form starts an instance. Read-only `GET /_platform/api/session` returns exactly `{email, role}` for the current session (sanitized401 otherwise); only the waiting page consumes it, once per page on entry, to show an administrator the plain link 「管理后台」 (`/_platform/admin`) in every state plus 「去配置模型」 (`/_platform/admin/models`) while `unconfigured`; failures add nothing and never navigate. Inside DSH, the image-delivered `plugins/platform-nav` client registers one `sidebar.footer.action` entry: 「账号设置」 for everyone and 「管理后台」 only when the instance was started for an administrator (overlay row `config.admin`, published by its host half as the `__DSH_TEAM_PLATFORM_NAV__` page global; no network request). The same row's `config.pluginCatalog` (package → `forced-on`/`forced-off`, forced catalog items only, catalog order) rides that global; the client then hides each forced package's native bundle switch on its plugin-page card and detail top through one injected style, and inserts one inert 「已开启 · 由管理员设定」/「已关闭 · 由管理员设定」 marker after it, never modifying DSH nodes. A missing `pluginCatalog` reads as empty; an invalid one fails the host half loudly with `TypeError`. Role changes apply at that user's next instance start; admin pages and APIs still enforce the role. Every platform page shares one light frosted-glass system built on `:root` style variables (drifting background glows that stay still under reduced motion, glass surfaces with a near-opaque fallback without `backdrop-filter`, local system fonts only). Login and registration keep the two-column brand/form layout (stacked at narrow widths); waiting and account pages are centred glass cards; administrator pages place `AdminNavigation` in a glass sidebar beside one content panel, becoming a top bar that scrolls within itself at narrow widths. Each page retains desktop/narrow screenshots through the shared `expectViewportLayout` helper, which rejects horizontal page overflow. Browser tests use an owned local upstream only to prove authenticated landing, not to claim real DSH.

The platform account-settings link opens `/_platform/account`, not a DSH-native menu. Password change and logout share a synchronous pending fence and use only existing same-origin APIs. Password204 keeps the replacement HttpOnly session and clears fields; logout204 clears the cookie and navigates to the fixed login page. Browser evidence proves wrong-current401, old-session revocation, old-password rejection and new-password login. A Chromium `net::ERR_ABORTED` is accepted only for the exact POST request identity with observed204 and independently proved committed effects; all other request failures remain failures.

The waiting page starts through the existing JSON{} POST on entry or manual retry, and serially polls GET only while starting. Valid current-attempt running200 navigates to `/`;401 returns to login. Full, unconfigured, stopped and failure states stop polling and allow manual retry; departure cancels owned work. Its browser suite uses substitutes only for start/status APIs, preserving real compiled assets, platform login and authenticated local landing. These UI state tests do not claim real Docker startup.

The administrator account page uses the existing users-list API as its authority probe:401 returns to login,403 shows no-permission without rows/actions. Search/pagination and confirmed disable/enable/password-reset use only existing APIs; obsolete reads cannot overwrite current state, and one pending fence prevents duplicate mutations. Responses are consumed before settlement/navigation, including empty204; no PUT/GET transport failure is allowlisted. Browser mutation evidence uses the real service's no-instance stop path with an owned unavailable Docker socket, not a fake lifecycle service. Synthetic receipts are limited to list failure and an explicitly rendering-only empty response; loading/pending controls hold then continue real requests. Successful actions/auth remain real.

The administrator audit page shares implemented navigation with accounts and uses only the existing audit-events GET as its current-authority probe:401 returns to login,403 removes rows and controls. Explicit event/exact actor-or-target email/local-millisecond inclusive time filters reset page1; pageSize20 has no invented total, and an empty page after a full terminal page retains previous navigation. Loading, true empty, no-match and safe failure/retry remain distinct. Completed response bodies and current-attempt ownership fence stale data/authority and departure; only safe metadata is rendered, with no mutation/export/content controls. Browser verification requires real filtered identities/order, current authority and unchanged audit snapshots; loading holds one real GET and failure substitutes one exact500 before real retry.

The administrator instance page uses the existing instances-list GET as its authority and snapshot source. It shows five persisted states, nullable timestamps and expandable saved safe error/log text, with local email filtering and distinct loading/empty/no-match/failure states. Single restart/reset require explicit confirmation; reset states “会恢复该用户的 DSH 设置，文件和对话保留”. Current authority, stale reads, departure and a synchronous pending fence preserve the existing browser conventions; all response bodies settle before refresh. Restart200 is admission, not readiness, and reset204 does not auto-start. Its browser mutation lane uses the real HTTP/service/SQLite path with the existing owned Unix Engine dependency, not synthetic successful API receipts; physical DSH/profile preservation remains Docker evidence. No new request-failure exception, raw-log endpoint, polling or bulk action is introduced.

The administrator Office page `/_platform/admin/office` uses only GET/PUT `/_platform/api/admin/document-server`; its GET is the current-authority probe (401 returns to login once, 403 shows only no-permission). It shows the mode, and for the bundled server whether the deployment configured it (otherwise 「自带 Document Server：未配置，Office 不可用」 while the external form stays usable); the JWT appears only as 已配置/未配置 and the field is cleared on every load and save. Saving external sends `{ mode: 'external', url, jwtSecret? }` (omitted JWT keeps the stored one), 「切回自带」 sends `{ mode: 'bundled' }`; the page rejects an empty address, a blank JWT and a first switch without a JWT before sending, and maps the paired 400 by its exact message. One pending fence covers load and saves, departure aborts, and every change applies at an instance's next start.

## Verification notes

- Platform UI also covers instance five-state/time/safe-log rendering, four list states, current authority and confirmed restart/reset API/audit effects with the explicitly substituted owned Unix Engine dependency; the real Docker lane owns physical recovery proof.

## Evidence required: Platform UI

Verify with: Built React rendered by pinned Playwright Chromium over owned real platform HTTP/SQLite. Command: `pnpm test:ui`.

Real login/registration/password/logout and session effects; waiting four-state/manual retry/serial polling with only start/status API substitutes; administrator denial/search/pagination/four list states and confirmed disable/enable/reset with real API/SQLite effects (synthetic empty list is rendering-only); audit shared navigation, real event/email/inclusive local-time intersection, tied page20/no-total terminal paging/reset, four states/retry and current authority with unchanged audits/no mutations (only one held real GET or exact500 failure control); local assets, screenshots, zero unexpected console/page/request failures and external requests
