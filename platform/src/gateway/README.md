# Gateway

Admission, HTTP and WebSocket forwarding, and connection ownership of the platform gateway.

Moved verbatim from the root `AGENTS.md`; normative behaviour lives in the OpenSpec specs (`openspec/specs/`, `openspec/changes/`). Keep this file current in the same change as the code it describes.

## Admission, forwarding and connection ownership

- Gateway admission reserves `/healthz`, `/_platform` and `/_platform/` descendants, judged on the router's path (`routerPath` in `platform/src/request-path.ts`): the target is truncated at the first `?` or `#` and decoded with `decodeURI`, so `/%5Fplatform/x`, `/%68ealthz` and absolute-form or fragment-bearing targets are reserved too; reserved-character escapes such as `%2F` stay undecoded and are forwarded verbatim, and an undecodable target is platform404 for HTTP and upgrades alike. Unknown reserved paths stay platform404, except that an undeclared path under `/_platform/instance-api/ragflow/` answers401 without a valid instance token (platform404 after authentication). Other paths require a current active platform session. Anonymous GET/HEAD accepting explicit positive-quality `text/html` redirects to `/_platform/login`; other anonymous requests and upgrades receive401. `buildApp(config, database, logDestination, resolveUpstream, instanceService)` retains the synchronous resolver construction seam receiving only the authenticated user ID; a supplied instance service owns production resolution. It returns `{ outcome: 'running', host, port, cookie }` or an explicit stopped/starting/full/error/unconfigured outcome, never undefined. Unavailable HTML GET/HEAD redirects to fixed `/_platform/wait`; other requests receive503 with that `reason` code. Offline construction without either resolver/service retains stopped gateway behavior. HTTP forwarding strips client Cookie and hop-by-hop headers before trusted Cookie/Host injection, strips response Set-Cookie and trailers, and pipes without body parsing. Every forwarded HTTP response merges `Cookie` into `Vary` (absent → `Cookie`; an existing `cookie` or `*` token unchanged), and an admitted request carrying `Service-Worker` gets a sanitized403 without forwarding. A request with more than one `platform_session`, or a login/registration with any, stays anonymous for admission but its response (rejected upgrades included) appends expiries for the non-root ancestor paths in host-only/`Domain`/HTTPS `Partitioned` forms, plus nameless expiries for a bare `platform_session` fragment, only when the query-stripped path is at most256 RFC6265 cookie-path characters (no `;`) in at most8 segments; they follow a fixed priority (named host-only deepest first, nameless host-only, `Domain`, `Partitioned`) and stop within a3KiB `Set-Cookie` budget. A named, unpartitioned host-only `Path=/` expiry is never sent. Login and wait rendering remain separate UI tasks.

- HTTP responses for better-sidebar's workspace-file route carry `content-security-policy: sandbox` (replacing any upstream value) and `x-content-type-options: nosniff`, whatever the method or status, so a workspace file opened as a document runs in an opaque origin and cannot act for the employee on the platform origin. The match uses DSH's own rule on the target forwarded to it (`requestTarget`): the `new URL(target, 'http://x')` pathname equals `/sidebar/file` or starts with `/sidebar/file/`; an unparsable target fails closed. Subresource loads (`<img>`, fetch) and downloads are unaffected; every other path's headers are unchanged.

- Task11.4 adds WebSocket forwarding through that same resolver after session admission, exact single `PLATFORM_PUBLIC_URL` Origin validation (otherwise403), and a WebSocket-only Upgrade check (otherwise400). Handshakes retain protocol negotiation but strip client cookies and response Set-Cookie, including101. Both parser head buffers and frame bytes stream unchanged; peer cancellation/error and app shutdown release paired sockets. Unavailable outcomes reject with503 JSON reason, exact byte Content-Length and closure, never an HTML redirect. Failed upstream handshakes and thrown resolver failures yield sanitized502, never another response after101. Platform mutation Origin/JSON policy is unchanged and shares the canonical Origin predicate. Task11.3 separately qualifies large-transfer RSS.

- Pending WebSocket client bytes start flowing to the selected raw upstream only after its HTTP request headers finish writing (or a validated101 proves receipt); reverse traffic remains gated on101. This keeps early-frame bytes ordered and lets a small buffered client FIN cancel a delayed handshake without accumulating a second buffer. Ordinary TCP backpressure is retained; an unread FIN behind a fully stalled stream is not independently observable through public Node APIs. Application shutdown explicitly destroys its owned streams; no hidden handshake timeout or byte-discard policy is introduced.

- Established orderly EOF stops further stream admission but retains writes already accepted by both destinations. Upstream writable completion precedes client writable completion and paired release, so a normal upstream auto-close cannot truncate a pending client write. Transport errors, cancellation and application shutdown still interrupt draining and destroy owned resources.

- `buildApp` exposes the server-side `app.disconnectUserConnections(userId)` function. Its per-application registry destroys the user's currently active HTTP responses and pending/established WebSockets and waits for captured client-resource closure; existing transport cleanup releases their upstreams. HTTP completion unregisters the response rather than pinning a user to a reusable keep-alive socket. Disconnect is one-shot, not a user ban. Gateway-owned one-second non-renewing session checks close resources established by deleted, expired or disabled sessions without closing another valid session of that user; storage lookup errors fail closed with fixed sanitized logging. Tokens remain only in live ownership memory, never persisted or logged. App preClose clears the unreferenced timer, fences forwarding and closes all owned resources, including anonymous rejected upgrades.
