# Administrator APIs

Contracts of the administrator configuration routes under `/_platform/api/admin/`.

Moved verbatim from the root `AGENTS.md`; normative behaviour lives in the OpenSpec specs (`openspec/specs/`, `openspec/changes/`). Keep this file current in the same change as the code it describes.

## Configuration routes

- Administrator GET/PUT `/_platform/api/admin/model-config` owns shared model settings in the existing private0600 SQLite database. The model key is stored there per design decision2, never returned: HTTP exposes only `apiKeyConfigured`. PUT requires address, models and a listed default; omitted `apiKey` retains the stored key, a nonblank value replaces it, and blank values are rejected. GET/PUT never connect to the model or restart instances. The only platform model connection is the explicit administrator `POST /_platform/api/admin/model-config/test` (empty JSON body, current-authority recheck after the body): it reads the saved address/key/default model, sends one non-streaming `max_tokens: 1` completion to the DSH-identical URL (`/chat/completions` appended, no `/v1` added) with no redirects, a 20s deadline and a 64KiB body cap, and returns only a closed-set `{result, httpStatus, elapsedMs}`; the key, upstream body and URL never enter responses, logs or audits, and client disconnect or application close aborts it. Success proves the platform container's path, not employee-instance egress.

- Administrator model/runtime configuration mutations share a commit boundary that rechecks the current active administrator session after receiving the body, inside the settings/audit transaction. Audit failure rolls back the save; raw parse/storage errors and credentials never enter responses or logs. These HTTP and custody cases run under `pnpm test:integration`; source/dist file-database reopen evidence accompanies changes to this surface. RAGFlow connection configuration (below) shares this boundary.

- Administrator GET/PUT `/_platform/api/admin/plugin-catalog` lists the shipped plugin catalog (`images/dsh-user/catalog.json`, read once at app construction relative to the `platform/src/plugin-catalog/` module, so a missing or malformed file fails `buildApp`) with each entry's `state`: `required` entries are always `forced-on`; `manageable` entries carry the stored tri-state (`employee` default, `forced-on`, `forced-off`). PUT takes exactly `{ entries: [{ id, state }] }` covering every catalog id once; a required entry with any other state, an unknown, missing or duplicate id, an unknown state or extra keys return a fixed 400 without mutation or audit. Saves store only manageable ids under the `pluginCatalog` setting through the shared commit boundary and record `plugin-catalog.updated`. Migration 5 seeds four settings rows with DSH 0.2.1-rc.2 defaults: `pluginCatalog` `{}`, `pluginRegistries` `["https://registry.npmjs.org/","https://registry.npmmirror.com/"]`, `registryProbeEnabled` `true`, `webToolsEnabled` `false`. The managed overlay generator consumes all four (`platform/src/managed-config/README.md`). Changes apply at an instance's next start.

- Administrator GET/PUT `/_platform/api/admin/plugin-sources` reads and writes the seeded `pluginRegistries` and `registryProbeEnabled` settings as one save unit through the same commit boundary (admin recheck after the body, same-transaction `plugin-sources.updated` audit with no details, `runningInstances` in the PUT response). GET returns exactly `{ pluginRegistries, registryProbeEnabled }`; PUT takes exactly that object: a non-empty array whose every item matches DSH's `REGISTRY_URL` (`^https?://\S+$`, the single implementation exported from the `db` module) and a strict boolean. Envelope, boolean or empty-list violations return a fixed 400; an invalid item returns a 400 naming only `pluginRegistries[<index>]`, never the item, because registry addresses may carry credentials, which are accepted, returned to an authenticated administrator, never logged or audited, and, since the overlay writes them, readable inside every employee instance (see `platform/src/managed-config/README.md`). The first item is DSH's `registry`, the rest its `fallbackRegistries`; the platform does not dedupe, normalise or cap the list. `patch` may throw the exported `ClientConfigValidationError` inside the handler's pre-transaction `try`; the other configuration routes' `patch` never throws and their behaviour is unchanged. The overlay generator writes both values at every start (see `platform/src/managed-config/README.md`); the administrator page `/_platform/admin/plugins` edits them, and changes apply at an instance's next start.

- Administrator GET/PUT `/_platform/api/admin/web-tools` reads and writes the seeded `webToolsEnabled` setting as its own save unit through the same commit boundary (admin recheck after the body, same-transaction `web-tools.updated` audit with no details, `runningInstances` in the PUT response). GET returns exactly `{ webToolsEnabled }`; PUT takes exactly that single-key object with a strict boolean, and anything else returns the fixed 400 without mutation or audit. The overlay generator removes `@deepseek-ai/dsh-tool-web` from every preset and pins the root `tool-web` row disabled only while this setting is `false`; `true` leaves both alone. Changes apply at an instance's next start.

- Migration 6 seeds six RAGFlow settings rows: `ragflowBaseUrl` `""`, `ragflowApiKey` `""` and the retrieval parameters `retrievalTopK` `8` (returned chunk count, integer 1..100), `retrievalSimilarityThreshold` `0.2`, `retrievalKeywordsWeight` `0.7` (finite 0..1) and `retrievalRerankId` `""` (rerank model ID, empty for none); their RAGFlow request mapping is design decision 3. Administrator GET/PUT `/_platform/api/admin/ragflow-config` reads and writes only the address and key through the shared commit boundary (admin recheck after the body, same-transaction `ragflow-config.updated` audit with no details, `runningInstances` in the PUT response). GET returns exactly `{ baseURL, apiKeyConfigured }`; the key is stored in SQLite and never returned, logged or audited. PUT takes `{ baseURL, apiKey? }`: omitted `apiKey` keeps the stored key, a nonblank value replaces it, and a blank, non-string or extra field returns the fixed 400 without mutation or audit. `baseURL` must satisfy the single exported `isRagflowBaseUrl` rule (at most 2048 characters, no whitespace, C0 control characters or DEL, no `?`, `#`, `@` or `\`, and an `http:`/`https:` URL); it is stored verbatim, path included, so appending `/api/v1/...` never lands in a query or fragment. The connection test and the instance proxy (`platform/src/ragflow-proxy/README.md`) read RAGFlow; the administrator page `/_platform/admin/knowledge-base` edits them together with the retrieval parameters below and runs the connection test, showing one fixed Chinese line per result and the RAGFlow version on success.

- Administrator GET/PUT `/_platform/api/admin/retrieval-config` reads and writes exactly the four seeded retrieval parameters `{ retrievalTopK, retrievalSimilarityThreshold, retrievalKeywordsWeight, retrievalRerankId }` as one save unit through the same commit boundary (admin recheck after the body, same-transaction `retrieval-config.updated` audit with no details, `runningInstances` in the PUT response). PUT requires all four keys and replaces them; any other envelope returns the fixed 400. Value domains are the settings layer's (integer 1..100, finite 0..1, string) and a violation returns 400 naming the field plus the allowed domains, without mutation or audit. The route additionally rejects a non-empty `retrievalRerankId` with surrounding whitespace (design decision 3), since the proxy sends a non-empty value verbatim as RAGFlow's `rerank_id`; no message echoes input. The instance proxy's retrieval route applies them on every request.

- Migration 7 seeds `documentServerUrl` `""` and `documentServerJwtSecret` `""`. Administrator GET/PUT `/_platform/api/admin/document-server` chooses between the bundled Document Server and an external one through the shared commit boundary (admin recheck after the body, same-transaction `document-server-config.updated` audit with no details, `runningInstances` in the PUT response). The mode is derived from storage by the `db` export `documentServerMode`: a non-empty `documentServerUrl` is `external`, otherwise `bundled`. GET returns exactly `{ mode, bundledConfigured, url, jwtConfigured }`: `bundledConfigured` is the deployment fact `config.documentServer !== null`, the only bundled value `app.ts` passes to the admin module (`documentServerBundled`), so the bundled container name and JWT never reach it; `url` is the stored external address (`""` when bundled); `jwtConfigured` reports a stored external JWT, which is never returned, logged or audited. PUT takes exactly `{ mode: 'bundled' }`, which clears both stored values, or `{ mode: 'external', url, jwtSecret? }`: `url` must satisfy `isRagflowBaseUrl` and is stored verbatim (a trailing `/` is stripped where it is used); a present `jwtSecret` must be a non-blank string, stored untrimmed, and replaces the stored one; an omitted one keeps it. Any other shape is the fixed 400 without mutation or audit. Inside the transaction the merged settings must have the address and JWT both empty or both set, so a first external save without `jwtSecret` returns 400 `External Document Server requires jwtSecret` and rolls back. Nothing reads these settings yet (the orchestrator and overlay consume them in later stage-2 tasks); changes apply at an instance's next start. The administrator page `/_platform/admin/office` edits them.

- Administrator `POST /_platform/api/admin/ragflow-config/test` (empty JSON body, current-authority recheck after the body, no audit, no settings write) and the instance proxy (`platform/src/ragflow-proxy/README.md`) are the only routes that contact RAGFlow. It sends at most two GETs through the single RAGFlow HTTP client in `platform/src/ragflow-proxy/` (imported only through its `index.ts`; the stage-2 proxy extends it rather than adding a second client): `<base>/api/v1/system/version` without the key (RAGFlow v1.0.0-rc2 serves it unauthenticated), then, only when that answered `code: 0` with a version of 1–64 printable ASCII characters, `<base>/api/v1/datasets?page=1&page_size=1` with `Authorization: Bearer <key>` to prove the key; trailing `/` are stripped from the stored address before the path is appended. Each request has the fixed `RAGFLOW_TIMEOUT_MS` (10s, through the end of the body), `redirect: 'manual'`, a 64KiB body cap and no retry; client disconnect or application close aborts it, and application close answers the fixed 500. The response is `{ result: 'ok', version }` or `{ result }` with `not-configured` (address or key empty, key unusable as a header, HTTP401/403 or `code: 401`), `timeout`, `unavailable` (transport failure) or `upstream-error` (3xx, other non-2xx including404, oversized or unparseable body, non-zero `code`, invalid version). Success is decided by the body `code`, not the HTTP status. Logs carry fixed text and the result only; the key, address and upstream body never enter responses, logs or audits. The 64KiB reader is shared with the model probe through `platform/src/bounded-body.ts`.

- GET/PUT `/_platform/api/admin/runtime-config` exposes only `idleMinutes`, `cpuCores`, `memoryMiB`, `maxRunningInstances` and `defaultPermissionTier`. PUT requires all five raw fields; integer scalar domains are 1..9007199254740991, CPU is finite and positive (fractional cores allowed), tiers are approval/auto/yolo. Saves additionally reuse the existing subnet-pool validator to reject a running limit above configured /28 capacity with400 and full rollback, preserving the boot invariant (default /16 allows4096; /28 allows1). Model configuration is preserved. Capacity admission rereads the saved limit on the existing orchestrator owner; changing it does not retire existing instances. Docker-unit representability remains checked at startup; this API introduces no new host-budget policy, scheduler or permission-preset mapping.
